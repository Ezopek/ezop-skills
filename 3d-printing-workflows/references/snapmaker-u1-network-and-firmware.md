# Snapmaker U1 network connectivity and firmware staging (optional vendor-specific reference)

Observations from specific units and firmware (1.4.x to 1.5.x). They are leads, not guarantees; check the vendor's current documentation. Use placeholders for networks and addresses; never record real SSIDs, passwords, router credentials or addresses in a skill or report.

## 1. Wi-Fi: protected network will not join

Symptom: 2.4 GHz networks discovered inconsistently and an open network joins while protected ones fail. Diagnose an association or compatibility failure, not a proven bad password. Firmware 1.5.1 had no Wi-Fi fix and 1.5.2 beta notes covered first-layer and nozzle issues, so do not promise an update fixes it. Never advise leaving an open access point enabled.

Isolation comes before any compatibility weakening. The relaxations below (WPA2-only, PMF off or optional, no WPA3) belong only on a dedicated SSID that has first been verified as an isolated IoT VLAN, a guest network or an equivalent set of restrictive ACLs, with no route to trusted devices or the main network. If isolation is not verified, do not weaken anything: report what is missing and stop. Never lower the security of the main or trusted network, and never extend blanket trust to the printer's network. This reference does not prescribe a network change; making one is the owner's decision.

First safe configuration: enable the printer's Maximum Compatibility, forget the prior network, reconnect. On the router use a dedicated 2.4 GHz IoT SSID (Smart Connect and band steering off), WPA2-Personal with AES only (no WPA3, no transitional mode), PMF off or optional (never required), 20 MHz, a manual non-overlapping channel (1, 6 or 11, chosen after a congestion scan), 802.11b/g/n mixed if needed, and consider disabling fast-roaming extras (11r/k/v). Router admin UIs can show an option as changed without saving it; do a hard reload or a re-login and verify the stored values before asking the user to retest, and before attributing a failed retry to the printer. If a verified profile still fails, stop weakening the primary network, do a non-destructive cold power cycle and re-add the SSID before considering any reset; a factory reset that may erase calibration data needs explicit approval.

Observed bootstrap workaround (one unit, not a proven fix): joining an open hotspot first and then switching directly to the protected SSID while connected let the WPA2 network associate; after a cold boot Maximum Compatibility had reset to Off, and re-enabling it and refreshing the list reconnected to the saved SSID. Network discovery sometimes needed several refreshes. The unit later vanished from the network (ARP entry incomplete, no Moonraker host on a scan); treat spontaneous post-association loss as a separate support symptom and test another cold reboot with the open hotspot unavailable. Verify recovery from the LAN (web on TCP 80, Moonraker on TCP 7125, repeated HTTP 200 health requests, `klippy_state: ready`).

An incorrect printer clock (no NTP while offline) should not block WPA2-PSK association (the handshake does not use wall-clock certificates); record it as evidence but do not chase it.

Escalation: the vendor's log path is Settings, About, System Log, export logs to USB (FAT32, EXT2 or EXT4, 64 GB or smaller). Exports may hold only encrypted `content.enc` and `key.enc`; keep the original archives, record size and SHA-256, map each to the test sequence from contemporaneous notes, disclose a wrong clock in filenames, and do not claim to interpret the encrypted payload. Email providers may reject tens-of-megabytes exports; further compression will not shrink them. Prefer a reply without attachments asking for a secure upload route, listing filenames, sizes, hashes and the test each represents; split volumes are a last resort; verify hashes on the destination after staging a support bundle.

"Disconnect and reconnect the Wi-Fi antenna" normally means reseating the thin coaxial lead at its tiny snap-on U.FL/I-PEX-style connector, only while powered off, pressed flat and vertically without levering, not removing the shielded module.

## 2. Wired fallback with a USB Ethernet adapter

USB-A Ethernet is a credible but officially under-documented workaround (vendor staff confirmed the intended path; owners report plug-and-play DHCP). Do not infer compatibility from a USB-A connector or generic "Linux compatible" marketing. Chipset matters: prefer ASIX AX88179 / AX88179A / AX88179B and check that the listing names the chipset (vendors revise internals). Stock and Extended kernels expose several driver families (`ax88179_178a`, `asix`, `r8150`, `r8152`, `cdc_ether`). Avoid unspecified chipsets and RTL8156 2.5 GbE models whose firmware blobs may be missing; 2.5 GbE buys nothing for printer traffic. The vendor stated the USB-A output is 5 V / 0.4 A, so prefer a plain bus-powered dongle over an unpowered hub. Evidence hierarchy: strongest is `dmesg`/`lsusb` registration and DHCP success for the same model and revision; strong is a supported chipset in the kernel plus a fixed-chipset listing; weak is marketing text.

Test: router or switch port with DHCP; connect Ethernet to the dongle then the dongle to the printer; cold-boot with the dongle attached; check the router's lease list; test the web UI by IP (Wi-Fi can then be disabled for an unambiguous test). If no link or lease appears try one reboot and test the adapter on another Linux device (a reported failure was a defective adapter). Do not install custom firmware merely to test a supported chipset.

DHCP reservation: confirm the host through Moonraker `/machine/system_info` (machine type, active interface, MAC, address), match the exact **wired adapter MAC** in the router's client list, add a separate enabled reservation for it (an existing reservation may belong to the Wi-Fi interface; do not edit or replace it silently), keep the working address unless a change was requested, verify the reservation table (not just the transient client list), then re-probe Moonraker for ready (the lease may not show permanent until renewal). When automating a router UI over a self-signed certificate scope the relaxation to that automation context, not system-wide TLS; scope selectors to visible elements (UIs may render hidden duplicates) and verify after every state-changing click; keep any router secret in memory only, never in arguments, scripts or screenshots.

## 3. Staging official firmware on a USB drive

1. Resolve the exact version from the vendor's official firmware release-notes page and follow its download link; never guess a CDN filename. If support requested a specific (even older) version, use exactly that.
2. Download over HTTPS with failure handling (for example `curl --fail --location --proto '=https' --tlsv1.2`) to a same-volume `.part` file, verify byte count and SHA-256 against the official source where published, and rename atomically to the original filename. Treat sizes and hashes in old notes as session evidence, not a substitute for resolving the current link.
3. Identify the removable device positively before writing (`lsblk -o NAME,PATH,TRAN,RM,HOTPLUG,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINTS,MODEL`; the `RM` flag is only an advisory hint, not proof and not a requirement: some USB media report `RM=0` and `RM=1` alone identifies nothing. Identify the device positively from `TRAN=usb`, the device and partition model, the connection path and a capacity that matches the intended media, and refuse on any ambiguity or when it could be an internal or system disk, including an internal disk mounted under a removable path). Use media of 64 GB or smaller, FAT32 (least surprising), EXT2 or EXT4. Mount the exact partition read-write, inspect free space and root contents, never overwrite a same-named file silently.
4. Copy the original `.bin` into the drive **root** (a file elsewhere may not be found by Local Update), without unpacking or renaming. `sync`, compare source and destination SHA-256 (and `cmp --silent` when both are readable), unmount, and verify `findmnt -S <partition>` shows no active mount before saying it is safe to remove.
5. Printer side: Settings, About, Firmware Version, Local Update, select the package, confirm. Keep power stable and do not remove the drive during installation. Report the exact result and version afterwards.
6. Flashing is a device-control action: idle check, operator consent, and a known rollback or support path. For Extended firmware resolve the exact tagged release through the repository's release API (non-draft, non-prerelease, exact asset, size and published digest; never a rolling or development artifact) and check the stock base it needs.

Remote-workstation staging variant (only when the operator asks for the package to be staged on a different workstation): download or transfer only the exact qualified release into an operator-designated folder over an operator-approved transport, to a same-volume `.part` file; verify the byte count and SHA-256, then rename atomically to the original filename. Read the final file back on the destination workstation (path, size, hash) before reporting delivery, and only then copy the unchanged `.bin` to the USB root. A transport exit status of 0 is not delivery. This reference issues no remote command and writes to no device.
