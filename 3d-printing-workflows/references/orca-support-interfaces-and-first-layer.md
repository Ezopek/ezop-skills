# Orca first-layer colour, support interfaces, support roots and painted-top opacity

OrcaSlicer 2.4.x-class behaviour; verify against your version. Numeric values come from specific projects and are starting hypotheses, not presets. Apply the artifact identity gate and slice-from-embedded-settings procedure in `slicer-semantics-and-evidence.md` before any of this.

## 1. First-layer colour inheritance in a painted project

A painted 3MF combines two assignments: an object or part base `extruder` in `Metadata/model_settings.config`, and per-triangle `paint_color` attributes in the object model. Unpainted triangles inherit the base extruder. If a whole first layer uses one filament:

1. Hash the original; treat the 3MF as a ZIP.
2. Read the object or part `extruder` assignment and the plate `filament_maps`.
3. Stream-parse the referenced object model: vertex Z values and triangle `paint_color` tokens.
4. Find the transformed geometric minimum Z and classify triangles touching or within the initial-layer height.
5. Report painted labels and unpainted counts separately. A bottom with one explicit label plus unpainted faces inherits the base extruder, which explains a monochrome first layer.
6. Remedy: changing the base extruder swaps the one inherited colour; a genuinely multicolour underside must be painted with the intended colours and enough paint depth, then sliced and checked in Preview by filament or tool.

Do not infer first-layer labels from a plate thumbnail (it usually cannot show the underside). Do not export STL, which discards triangle painting.

Scope: painting colours or supports in a slicer UI is print-side tool assignment and stays in the printing workflow, including the repaint in step 6. Editing the 3MF file's mesh or paint data outside a slicer is standalone archive work for the geometry workflow.

## 2. PLA model with a PETG support interface

Using PETG only for the interface of PLA supports works because the materials adhere weakly; zero top and bottom Z distance can then give a well-supported surface that still separates. Treat it as a high-value **top-interface technique** for broad, well-anchored flat overhangs and dedicated multi-head printers, not a universal default. The deliberately weak bond is a failure mode for tiny islands, tall support feet that begin on the model, wet or stringy PETG and organic geometry.

Keep these distinct: **top interface** (under overhangs), **bottom interface** (where support lands on the model), **support body**, and **lateral XY proximity** (`support_object_xy_distance`; not automatically an interface, so need not use PETG). The top and bottom interface layer counts are separate controls, and zero is allowed for either (Orca's documentation of these settings describes them independently; verify the exact version and the printed paths, because it gives semantics, not a PETG physical validation: https://github.com/OrcaSlicer/OrcaSlicer/wiki/support_settings_advanced). Set both nonzero when the intent is dual-sided isolation of a DIFFERENT material at both zero-gap model-facing contacts, that is under overhangs and where support stands on the model. Merely allowing supports to start on the model does not force both. The top-only technique (bottom interface layers 0) stays a deliberate, qualified alternative, provided the bottom contact then keeps a normal detachable gap as described below. Assign PETG to `support_interface_filament`, leave the support base on the default model-compatible material, and set zero Z distances only after validating the material pair.

Interface transition semantics (verify): with at least two interface layers Orca prints the layer furthest from the model (the bonding layer) in the base filament. 1 layer: 1 interface layer; 2 layers: 1 interface plus 1 base bonding layer; N layers: N-1 interface plus 1 base bonding layer. Some PLA inside a three-layer dense interface is not proof that PETG was skipped.

`support_interface_not_for_body` (**Avoid interface filament for base**) affects the support body only; it does not repair a missing model-facing interface or an explicitly wrong body tool. Prove the emitted role and tool mapping in G-code. `flush_into_support` can make the body appear in assorted colours; disable it temporarily during diagnosis and inspect Preview by Filament or Tool with the layer slider.

If a PETG bottom interface acts as a slip plane, a controlled alternative is `Bottom interface layers = 0` with the body in model material and `Bottom Z distance` restored to a normal detachable gap (one layer, commonly 0.2 mm; 0.1 mm only if extra anchoring is worth the scarring). Never disable the bottom interface while leaving same-material support at zero bottom gap, because PLA on PLA at zero gap can weld. Prefer routing support to the bed, or larger painted contacts, when the model-facing top surface must stay pristine.

A safe starting baseline for a PLA model with PETG used only as top interface (illustrative; one validated project): body in model PLA; interface on the PETG tool; 3 top interface layers; top Z distance 0; top spacing 0; Rectilinear Interlaced pattern; bottom interface layers 0; bottom Z one normal layer; interface speed about 40 mm/s. Keep `On build plate only` off when trees must reach internal overhangs (enabling it can silently remove critical internal supports); verify before using it. Do not enable interface loops, enlarge tips or add global expansion reflexively when the corrected baseline already slices without branch warnings; make those later physical A/B tests.

## 3. Manual contact enlargement (what Orca does and does not offer)

Orca 2.4.2 has no per-island interface brush. The mechanisms and scopes:
1. **Support Painting** marks enforcer or blocker facets on the model. A brush or Smart Fill can mark a larger contiguous underside patch (disable `On overhangs only` only when adjacent sloped facets must be included). It can merge nearby islands but cannot paint empty air.
2. **Support enforcer primitives** select the model facets they intersect; they do not create a solid tower or arbitrary pad.
3. **Normal Support expansion** (`support_expansion`) changes the horizontal span of all normal supports, not one island; a small positive test such as 0.5 mm may stabilise micro-islands but can worsen removal. It made negligible difference under Tree Hybrid in a tested project.

For fragile micro-interfaces prefer: paint a larger contiguous underside contact where geometry permits, reduce interface speed, slice, inspect the `Support interface` toolpaths; use global expansion only if painting cannot enlarge enough; if no adjacent facets exist use controlled expansion or purpose-built sacrificial geometry.

## 4. Tree-support diagnostic pattern

With `On build plate only` disabled, branches may start on the model or run close to its sides. A branch-side region is controlled by XY clearance, not interface logic, so it may legitimately use the body material. If it appears to fuse:
1. Reproduce from a sibling saved with the failing setting (a project saved with `On build plate only` enabled does not preserve the failure).
2. Inspect layers by Filament or Tool and by feature type: top interface, bottom interface, body or lateral proximity.
3. Confirm top and bottom interface counts and Z distances independently; temporarily disable `flush_into_support`.
4. Check or cautiously increase `support_object_xy_distance` (about 0.40–0.50 mm is a practical diagnostic range for a 0.4 mm nozzle).
5. Compare Tree Hybrid with Normal/Snug (often more predictable when supports must start on the model, though it may use more material). On highly organic geometry Normal/Snug may produce thin contacts on hundreds of layers and many isolated material starts while Tree Hybrid consolidates them into fewer caps; compare generated toolpaths, not style names. Tree Strong can keep the same interface topology with an unnecessarily dense body; Tree Organic can stay solver-fragile.
6. Treat repeated `Potentially lost branch!, critical: 1` messages as topology warnings even if export succeeds.
7. Require a real sliced-preview comparison before calling it a slicer bug.

**Threshold angle:** support generates for overhangs whose slope angle is **below** the threshold. Lower means fewer supported slopes, fewer tiny PETG islands and fewer tool changes, but may leave decorative surfaces unsupported. Run isolated A/B slices (for example 30°, 25°, 20°) and choose by the user's quality-versus-cleanup priority. In one validated organic project 30° was the quality-first baseline, 25° a credible compromise that dropped some 25–30° slopes, and 20° removed too much decorative support; time, material and tool changes fell steadily.

## 5. Support roots that appear to start in the air

Orca does not simulate molten filament. It builds layer masks from model and support clearances and assumes a first support path can bridge or sag onto the model across the contact gap; this is intentional (zero gap with same-material support can weld). Distinguish `support_bottom_z_distance` (vertical release gap), `support_object_xy_distance` (lateral mask), `support_interface_bottom_layers` (fine interface paths at the root) and `support_object_first_layer_gap` (in 2.4.2 it affects the object's first layer at the plate, not a root born high on the model). On a sloped wall the combined masks can leave a tiny root island whose nearest model extrusion is lateral on the current layer but directly below only two or more layer centres later: valid to the slicer, physically fragile.

Layer-local birth test (aggregate projections are insufficient): parse extrusion paths per `;LAYER_CHANGE`/`;Z:` and rasterise `Support`, `Support interface` and model paths separately. For each support component on layer N compare with support on N-1 (tolerance covering line radius plus allowed tree motion), require overlap with support on N+1..N+3, classify the birth as body or bottom-interface dominated, search model paths on N through about N-6 and report nearest XY distance and Z delta, and render locally. A component with no support below, future continuity and a model overlap 0.4 mm lower at 0.2 mm layers is an intentional one-layer release bridge, not a physically anchored path. Raster area is a diagnostic proxy.

Safe A/B order (isolated changes before combinations): bottom interface layers to 0 keeping normal Z and XY; smaller bottom Z; smaller XY gap; zero bottom interface plus smaller XY; branch-diameter changes last. Rules: a same-material bottom interface can turn a tree root into fine rectilinear micro-islands and zeroing it often yields a wider closed body loop that still detaches; a smaller requested Z gap may quantise to the same layer separation (verify emitted Z values, not the GUI decimal); smaller XY clearance may barely reduce births and worsen removal; `Bottom Z = 0` is not a generic fix for same-material support; a larger branch diameter can crash the Tree solver on tight organic geometry (a nonzero return or missing G-code rejects the variant); `On build plate only` can delete internal supports that cannot route from the bed.

Selection: choose on birth counts and small-birth area distribution, local geometry at failing coordinates, interface components and weak or critical coverage heuristics, tool changes, time, material, lost-branch warnings and removal access. Prefer the least invasive variant that turns fragile interface strings into coherent body feet. Install only a sibling: re-hash the live source, verify all ZIP members except `Metadata/project_settings.config` are byte-identical, require an exact declared settings diff, copy without clobbering, read back CRC and SHA-256. A small physical test remains the final proof of adhesion, removal and marking.

## 6. Local opacity underlay below a painted top surface

Use when a light painted surface is one sliced layer thick over a dark base. Prove the real per-layer stack at a world XY first: freeze the input identity, slice that exact copy retaining G-code, map display layers to `;LAYER_CHANGE`/`;Z:` (do not assume zero- or one-based numbering), decode tool colours from `filament_colour` or the G-code config (Preview hue and tooltip colour can disagree), parse positive-extrusion segments per layer including `G2/G3` at the target XY, and confirm the stack (for example `T0,T0,T1`).

Version-specific pitfalls seen in 2.4.2: `interface_shells=1` may add shells without changing the material stack at a painted boundary; a global `internal_solid_filament_id` can lose to painted-region segmentation; `Metadata/layer_config_ranges.xml` with `internal_solid_filament_id` segfaulted in one project (gate with an actual slice); a parameter modifier can keep selector metadata and still fail to override painted segmentation; a fully enclosed overlapping part may be merged into the main solid; a closed nested cavity can be repaired back into the main solid, so a local material part must reach the external surface; raising global top-shell layers adds time and material without changing assignment.

Local surface-open material part: building, aligning and positioning the closed solid is geometry work, so do it in the geometry workflow (or a qualified geometry backend), not as a slicer setting. Printing decides opacity and material intent and verifies the resulting slice. Steps: build a small closed part assigned to the desired filament for all roles, align to the local normal, extend inward to the desired opacity depth, let its top reach the existing surface by a controlled amount, keep its maximum Z below the plane that would create the next display layer, slice and require consecutive desired-tool coverage at the exact XY with no overlap by the other tool, and inspect local per-layer renders to confirm it connects to the painted area. What printing proves is the slice, not the solid: prove quantisation in G-code. Without a geometry workflow or qualified backend that can really build and position the solid, this is not a finished geometry repair; report it as provisional or NOT DONE, not as a settings change. Canonicalise with the same slicer version, slice the canonical file again (do not reuse pre-round-trip G-code), and verify the exact stack and roles, no added material on the next layer, unchanged layer count and maximum Z, no solver crash and ZERO validation failures (`FAIL: 0` when the validator reports that field), an empty settings diff unless intended, identical original paint-token counts, the added part still `normal_part` with correct extruder IDs, and ZIP CRC and SHA-256 after installation under a new filename. Increasing purge or flush cannot create colour depth; Preview hue alone does not prove tool assignment; a parser-successful file is not enough.

## 7. Experimental minimum-interface-path feature (if developing a slicer change)

The controlling criterion for tiny dissimilar-material interface starts is the **layer-local printable toolpath**, not aggregate 3D island area. Implement by changing legal contact geometry before final path generation, never by G-code post-processing, and never silently fall back from PETG to PLA at zero gap. Keep top and bottom controls separate, `0` preserving present behaviour exactly, and do not delete an unsatisfied contact as a hidden fallback. Work on a personal fork with an `upstream` remote and a dedicated branch; do not open an upstream PR before a reproducible fixture, deterministic slice evidence and physical A/B evidence exist.

Fixtures: (A) a PLA sphere of 30 mm diameter with its lowest point at Z=35 mm, Tree Hybrid, support from the plate only, PLA body, PETG interface, zero top gap, two top interface layers (baseline: one 2.74 mm PETG path of 0.925 mm² on the first interface layer); (B) a bowl plus floating sphere for bottom interface, classified from support geometry and contact surfaces, not merely the interface role or PETG selection (a flat inner floor reliably roots a PETG bottom contact; keep it as a control). A genuine PETG bottom root can form on a shallow external ramp (about 11° at 0.2 mm layers with Tree Hybrid, `support_on_build_plate_only=0`, zero Z gaps, 2 bottom layers) but not at 12.5°, not at 0.3 mm layers in the tested case, not with Tree Organic, and not on an equivalent inner bowl wall; do not claim every sloped wall yields one.

Plan-audit and falsification gates: inspect all positional and index consumers before mutating a polygon vector (in Tree Hybrid `roof_areas` is partitioned by `first_base_roof_area`); prove a legal non-empty donor exists at that exact layer; audit `gap_support_object` and `gap_object_support` separately and reuse existing collision helpers; any pre-fill length estimate must use that layer's flow and the same density and spacing clamping as the filler. With independent support-layer height, the live filler pitch is `resolved_spacing / resolved_density`, not a sum; capture actual inputs at the seam that feeds the filler. Assert the actual `contact_fill_pattern` (a human-facing `rectilinear` label may resolve to the support-base filler; `rectilinear_interlaced` resolved to genuine rectilinear in the tested path) and require `path_count > 0`. A finite synthetic sweep is measurement evidence, not an eligibility proof; no counterexample in a finite family is not a bound. Baseline full tests before edits; test disabled settings against an unset baseline for unchanged G-code; then install a separately named experimental slicer on the printer host (never replacing the stable one) and request same-material A/B prints with close photos and a one-word outcome (held, blobbed, detached, nozzle caught it).

Two further guards. A nonzero same-material gap does not make a micro-path printable, so any fallback needs explicit side-aware material and gap semantics. Use strict TDD with a negative control: a deliberately nominal control carrier must FAIL the live-vs-retired pitch sensitivity assertion before the live off-nominal case is restored; keep the actual-fill, non-empty carrier, pattern and parity checks. Disabled compatibility means unchanged geometry, extrusion and tool order (or a G-code comparison excluding config metadata); a config-metadata-only delta is allowed when new default-0 keys exist, so it is not byte identity against a build that lacks the keys. For a rectilinear test family obtain the actual even and odd interface-ID parities from the same slice, derive their live angles through `SupportParameters`, and include controlled translations perpendicular to the hatch axis. The plan audit also inspects the downstream hole and roof consumers of any polygon vector and has them regression-tested before an early mutation; a geometry-growth feature does not ship without a proven legal expansion path. Before any merge or expand mutation of geometry, require BOTH a defensible per-island decision contract and an attribution boundary; a chained or reordered extrusion path order is not island identity. Stage the work: the first vertical slice is settings and plumbing plus measurement, and a merge-only change follows only once the merge case is reproduced and those two preconditions hold. Behaviour for Normal and Organic contact layers is unproven and needs its own discovery step; do not assume that what holds for the Tree Hybrid seams generalises to it.

Reproducible falsification sweep (diagnostic only): keep top and bottom records separate. Each FFF test slices its own fixture, reads its own live carrier and invokes synthetic `Fill` locally; no shared state across binaries, files, environment, caches or test order. Capture spacing, density, source area, perimeter and hole count at the same filler-input seam. Attack a declared candidate such as `A / pitch + P` with valid thin scanline strips, sub-spacing zero-emission regions, narrow-neck dumbbells, holes/annuli, high-aspect slabs and phase-sensitive/comb forms. Log non-empty results with area, full perimeter including holes, live fill inputs, angle/parity, phase, path count, emitted polyline length and candidate ratio. A real `L > candidate` is an observed falsification. A deliberately sub-spacing region emitting zero paths is a separate overestimate witness, not an accepted positive carrier or a vacuous empty family member. Finding no counterexample in a finite family is not a proof, a bound, a product eligibility rule or permission to mutate geometry. Keep these diagnostics in explicitly selected FFF tests, not normal-suite output.

Before requesting physical A/B prints, run focused FFF tests in random order with multiple seeds and obtain local sliced-preview proof of the intended interface paths and tool/material mapping. This validates the sliced output only; it does not replace the decision/attribution gate or authorise a physical printer operation.
