# Parametric insert prototyping and public model release

Two related procedures: recover a fit envelope and prototype a storage insert with coupons first; and prepare a prototype for public release. Measurements and results below are illustrative.

## 1. Recovering the geometry before asking for measurements

1. Inspect the named original model and its licence.
2. If its source download is not readily accessible, look for a compatible public remix and recover the fit envelope from it instead of guessing from product-listing dimensions. Use only download paths the operator is allowed to use; if a file needs a login, use the operator's approved path. Do not scrape beyond what platform terms allow.
3. Measure the downloaded mesh but treat global bounds only as a first clue (raised holders, tabs and ribs can lie outside the bottom-contact profile). Slice horizontally at the intended contact height and report several nearby Z sections to expose taper, waists and asymmetry.
4. Reconcile those sections with a physical top-view sketch or station measurements. For awkward containers useful parameters are overall length, widths at both ends, minimum waist width, transition width, waist position and length, corner or cap shape, vertical taper scales and independent side and end clearances.
5. Respect upstream licensing. Prefer a fresh parametric part constrained by the recovered sections over redistributing or silently modifying restricted source meshes.

Illustration of why: a compatible remix reported global bounds of 185.0 × 77.4 mm; treating them as the bottom footprint gave a 184.0 × 76.2 mm coupon that did not fit a container with a molded asymmetric waist. A station-driven plan profile (narrow end, grip waist, transition, wide end) from a physical sketch corrected it.

## 2. Design pattern for a storage-only desiccant insert

- A broad, shallow open tray with a removable ventilated lid; spool flanges rest on rails so wound filament does not bear load; transfer a 1 kg spool's load to the tray bottom with posts rather than a thin lid span; retain beads with slots smaller than the minimum granule size; keep any sensor loose for the first experiment and design a holder only after fit and radio behaviour are proven; preserve height for the known spool size and verify the container's internal taper rather than its nominal volume.
- Reduced-order sizing and perforation questions are in the printing skill's desiccant references if installed.

## 3. Fit-first delivery gate

Never make the full tray the first physical print. Export cheap footprint outline coupons (roughly 1.0–1.2 mm high), preferably nominal, loose and extra-loose. The user verifies that each reaches the final position without force, wall distortion, waist interference or corner contact. Use the largest successful coupon to update effective side and end clearance before regenerating the full tray. Label the full tray a prototype until a coupon passes; mesh validity does not prove physical fit. A failed coupon is diagnostic evidence: find *where* it stops. If the container has an asymmetric waist, taper or molded grip, replace the primitive footprint with a station-driven profile instead of scaling it down. Keep a little clearance in flexible, imperfectly measured containers.

## 4. CAD and verification workflow

- CadQuery is a practical headless choice. If no system CAD package is present you can run it from an ephemeral environment (for example `uv run --with cadquery ...`); that installs software, so do it only where the operator allows. Put measured dimensions, station positions, taper scales and clearances in an external JSON file; export STL and STEP.
- For curved station-driven outlines do not assume an interpolating B-spline stays inside measured limits: unconstrained splines overshoot (one went from 65 mm to about 104 mm). Use bounded piecewise or cosine interpolation, sample densely, and assert the exported maximum width and length against the measurement envelope.
- Test-first geometry: write assertions for fit envelope, height, lid clearance, vent width, support count and bounds; observe the expected failure; implement the minimum parametric geometry; export tray, lid and coupons; load exports independently (for example with Trimesh) and require non-trivial files, watertight, consistent winding, positive volume and bounds matching intent; inspect an exploded preview (inverted rails, missing ledges, asymmetric perforation, collisions that scalar tests miss); package STL, parametric source, README, tests and a deterministic validator, and verify the archive itself.
- If a real slicer is available also slice once headless. Slicer absence is no reason to skip independent mesh verification.

## 5. Release boundary (before the repository or listing is public)

- Choose a neutral descriptive product name. Put the author's chosen public brand in metadata and attribution, not opaque internal codenames. Remove personal machine paths, nicknames, order and account data, and user-specific wording. Keep third-party reference meshes outside the tracked tree unless their licence allows redistribution. Leave failed prototypes out of the primary release surface or in a clearly marked archive.
- Before the first commit scan text **and filenames** case-insensitively for old codenames; generated ZIPs, previews, STL and STEP names, test expectations, validators and README examples often keep them.
- **Licence and attribution gate.** Identify every inspiration, compatible accessory, source mesh, remix, copied dimension set and borrowed asset; record each upstream licence and attribution requirement; decide whether the work is a derivative, an independent compatible accessory or a new implementation; keep the repo private with an all-rights-reserved notice until done; add chosen licences and platform-native remix links before publication. "Release candidate, licence pending" is honest for a private repo, not for a public listing.
- **Minimum artifact set:** README with problem, goals, status, compatibility and preview; parametric source and external parameter file; STL and STEP; orientation, settings and material guidance; regional parts list or search terms rather than one country's affiliate link; measured dimensions and a warning that nominal container volume does not prove internal compatibility; fit-coupon instructions; physical validation status, photos, known limitations and version; analysis and raw data for quantitative claims; attribution and licence. A fit coupon does not validate the complete tray; gate release on a full-part print and the functional test relevant to the model.
- **Make quantitative claims executable:** expose reusable geometry helpers and test documentation claims against them (vent-slot centres from one function used by CAD and tests; tests assert slot count, size and computed open area against the analysis inputs; effective parameters written beside exports; analysis scripts regenerate tables from explicit assumptions; an integration test proving model and analysis defaults agree).
- **Export and readback tests** run the real exporter in a temporary directory and require the exact expected output set with neutral filenames, non-empty artifacts, STL readback with vertex merging where appropriate, watertight, winding, positive volume and bounds, STEP readback as a valid solid, an effective-parameters file, and rejection of invalid JSON and unknown parameters. Inspect a rendered preview: a valid solid can be the wrong part.
- **Compatibility links and scope.** Keep evidence levels distinct: (1) inspiration or model link; (2) upstream reference container named by the original author; (3) purchase candidate that likely shares an OEM or mould (distinctive geometry and close dimensions, but no shared identifier or physical fit proof); (4) physically tested SKU, called verified only when exact identity is supported by order history or product markings plus a physical fit test. For cross-marketplace matching search EAN or GTIN first, then pack size, exact dimensions, unusual features and private-label aliases. Image feature matching can show promotional assets were reused but does not prove production identity or compatibility. Label candidate links visibly as candidates in the README, not only in chat. Put a feature-rich upstream alternative near the README top when users may otherwise assume the design supports printing directly from the box.
- **AI-assistance disclosure.** If AI materially assisted research, CAD scripting, analysis, documentation or tests, include a concise disclosure near the top; separately identify human-supplied measurements, physical fit checks and release responsibility. Avoid both hiding assistance and overstating autonomy.
- **Preview images:** rotate first, then trim with tolerance, reset the canvas and add an even border; check orientation, clipped lines, margins and README-scale legibility. Keep a reproducible render path or master image.
- **Private staging, if the operator uses a hosting service:** verify authentication and intended owner; create the repository explicitly private; add a focused `.gitignore` and confirm private references and delivery archives are untracked; run tests, export readback, privacy and secret scans and an independent review; push and read back visibility, default branch and remote SHA; require a clean worktree and local and remote SHA equality; inspect the first CI run's real conclusion. Do not report "uploaded" from local push output.
- **Selective CI.** For expensive CAD, export or analysis tests use a positive `paths` allowlist (geometry sources, parameters, analysis code and data generators, tests, dependency metadata, the workflow). Do not run the suite for prose or preview-only edits unless the suite validates those. Prove the filter with a workflow-only commit that runs green and then a docs-only commit that queues zero runs (poll for the normal delay before concluding "no run"). A new action major may not ship a floating major tag; pin an official exact release when required and rerun until annotations are clean.
- **Public-release gate:** full physical fit and load test; environmental or functional test complete; final photos and print profile; licence review done; community-facing filenames and prose; release archive regenerated from the tracked clean tree; fresh tests and CI green; platform description, tags, compatibility notes and version aligned with the repository. Changing visibility or publishing is the operator's decision.
