# Painted 3MF and project-file editing (colour-preserving)

Applies when the deliverable is a Bambu, Orca or Snapmaker-style **project 3MF** (a ZIP with `3D/...model`, `Metadata/*.config`, plate previews, per-triangle `paint_color`), or any multi-part or multicolour 3MF. For a plain single-material STL or a one-body 3MF without paint, use `stl-feature-audit-and-edit.md` instead.

Versions, tokens and file layouts here are examples from specific slicer releases. Re-verify against the actual file and slicer version.

## Non-negotiable delivery invariants

A *colour-preserving delivery* keeps, unless the operator explicitly accepts the named loss:

- **paint:** per-triangle `paint_color` tokens and their meaning relative to the filament palette (token counts per label before and after, every expected change explained);
- **parts, objects, components:** count, names, and which part is which body or colour region;
- **assembly transforms:** every build-item and component transform (a deliberate change is reported with before and after values);
- **project metadata:** printer, process and filament settings, plate and instance assignments, base `extruder` per object or part, palette and cardinality-coupled arrays.

Work on a clearly named sibling and keep the source immutable (hash before and after). A flattened geometry-only 3MF or STL is a **diagnostic or alternative sibling** (section D), never the completed delivery of a painted or coloured request. If colour-preserving delivery cannot be reached, the status is **NOT DONE (colour-preserving)** with the specific blocker, not "done with limitations".

## A. Portability, palette and slicer verification (ordered)

When moving a painted Bambu 3MF to OrcaSlicer, or to a printer with a different tool count, do not assume changing the printer preserves the colour map.

1. Inspect the 3MF as a ZIP before editing. `Metadata/project_settings.config` identifies the source printer and filament palette; `Metadata/model_settings.config` identifies plates, instances and base `extruder` assignments; `Metadata/plate_*.png` shows whether the project holds coloured and uncoloured duplicate plates; the model part may store per-triangle `paint_color`. Discover embedded `3D/Objects/*.model` paths from the ZIP instead of hard-coding a name.
2. **Resolve the colour mapping before mutating geometry.** A missing `paint_color` inherits the part or object base extruder. A numeric `paint_color` is a slicer-specific label, not a human colour name and not universally a palette index. Cross-check the base assignment, declared `filament_colour` palette, triangle-label counts and the rendered Preview. If moving one coloured region in a welded mesh, first identify which triangle set actually renders as the requested colour.
3. Distinguish **declared palette size** from **colours actually used by the selected plate**. A project can declare more filaments than the target printer supports even though one plate uses three. If painted faces reference later palette positions, switching directly to a printer with fewer tools can collapse them to filament 1.
4. Safe GUI sequence: select the coloured plate, delete deliberate uncoloured duplicate plates, remove unused filament entries so active colours renumber into the target printer's tool range, and only then switch the printer and process profile. After the switch, replace the source-vendor filament presets with target-compatible material profiles, preserving every tool/colour assignment. Keep the project as 3MF: exporting STL destroys triangle painting.
5. Diagnose the stage of failure before repairing. Wrong or gapped in **Prepare**: source triangle labels or part assignments. Correct in Prepare but wrong in sliced **Preview**: feature width, paint depth, wall generation or nozzle line-width limit. Correct in Preview but wrong physically: tool offsets, flow, ooze or machine calibration.
6. For dense single-mesh painting, prefer deterministic label repair over manual repainting (`paint-label-repair.md`). A vision model may audit renders but must not be the sole authority writing face labels (`vision-model-review.md`).
7. Treat headless validation as **version- and input-shape-specific**. Some slicer releases crashed on painted projects with certain command-line options while a later compatible release canonicalised and sliced a complete painted project from its embedded settings. For a full project try embedded settings first; use resolved external profiles for a raw STL or an explicitly incomplete or overridden project. Always prove the result by a face-level round-trip comparison plus actual tool commands in the G-code, never by exit code alone. When extending `filament_colour` manually, keep cardinality-coupled arrays (for example `filament_is_support`) aligned or the slicer can return a generic error. Do not force an older slicer through a newer project file and call that a gate.
8. For GUI validation in an isolated virtual display, process exit `0` and a screenshot file are not proof that the application launched: require a non-root application window and meaningful frame content (an image of only the root window fails the gate). Before capturing a real desktop, warn the operator and obtain approval; never make a capture indicator appear unexpectedly.

## B. Marker-guided geometric edits to a painted welded mesh

When asked for an exact change to part of a single welded, painted 3MF (raise or lower a coloured element, thicken a wall, set a clearance), **do not treat every triangle with that display colour as the edit region**. A paint label can span a planar face, its fillet, adjoining shell faces or unrelated fragments; moving the whole label can distort a neighbouring colour or body.

1. Preserve the original and create a named sibling. Re-open the **exact current source sibling** immediately before each audit or mutation; do not reuse an earlier scan after it was re-saved. Establish source hash, assembly or instance transform, palette and base-extruder mapping, and a table including the base label and every non-base token: face count, component count, local and assembled Z bounds, planar-fit status.

   **Before requesting temporary markers**, preserve the unmarked original and record which original paint and base-extruder assignments each marked surface will replace, including face lineage. A marked sibling is diagnostic input, not the final colour authority. If only the marked file exists, obtain the unmarked original or an explicit final surface-to-colour mapping; do not guess missing assignments.
2. For an exact gap, ask the user to paint **two deliberately chosen planar marker surfaces in two temporary colours**, state the target distance and which plane stays fixed. Map raw tokens to the visible marker colours from a freshly verified Preview or explicit mapping before calculating. Measure all relevant pairwise gaps in one declared frame. If stated dimensions and extracted geometry disagree, report the full marker table and pause. Move only the intended bounded volume or side, not an inferred whole paint region. If a marker colour includes a fillet, split or exclude the non-planar faces by plane fit and normal, or ask.

   **Remove temporary markers before delivery.** Restore their original paint and base-extruder meaning from the preserved unmarked source or confirmed mapping, carry it through moved and split faces, and explicitly assign new faces. Verify final per-surface assignments and the resolved palette against that colour authority, with topology deltas explained. Confirm no marker paint remains. Remove marker-only palette entries only after proving they are unused, maintaining cardinality-coupled arrays. Check the restored result in the slicer's colour Preview when available. Without enough evidence to restore the requested colours, keep colour-preserving delivery **NOT DONE** rather than handing over the marked diagnostic sibling.
3. For a Z translation, have the user mark both limiting planes and define that the volume between them along Z moves. Do not manufacture a broad bridge because two painted regions share vertices; first decide whether the result should be a solid extension, a separated clearance or a translated sub-volume.

   **Marker-plane segmentation gate:** resolve marker roles in the final slicer frame including every component, build and plate transform (a build transform can invert Z). Test the proposed bounded volume before writing: it must contain no marker surface declared fixed, and rigid translation plus Boolean recomposition must remain one connected solid. If the extraction contains a fixed marker or yields multiple solids, the planes do **not** uniquely define the moving sub-volume. Do not publish a plausible bridge or extend a neighbouring body; request one more marker along the intended retained seam or connector, or an explicit instruction to create a new connector from a named side or material.
4. Any topology-changing face move must preserve each selected perimeter edge's **directed** orientation. Sorting endpoints loses winding and can produce plausible output that the slicer flags as non-manifold. Duplicate only the moving-region vertices, rewire selected faces, stitch directed boundary walls consistently, then verify edge multiplicity is exactly two **and** the paired edges run in opposite directions.
5. Gate delivery with ZIP CRC and XML read-back, manifold, boundary and orientation checks, source and output hashes, and, where installed, a real slicer information or slice check. Do not claim the slicer accepts a custom 3MF from a homemade edge counter.

## C. Completion discipline for requested mesh edits

When asked for a finished 3MF artifact, own the diagnose, implement and validate loop. Do not message after every library or parser obstacle, and do not describe an attempted route as active background work when nothing is running. Continue until either (a) a named non-destructive sibling passed the declared validation gates, or (b) there is one specific, externally irreducible blocker. Then report the outcome with concise evidence.

## D. Flattened geometry-only sibling (diagnostic or alternative)

A canonicalised single mesh with no paint or project metadata is easy to mistake for a finished fix. Allowed only with these constraints:

1. It is a **diagnostic** to decide whether a bad placement or crash comes from the mesh or from the project container, or an **alternative sibling** the operator explicitly asked for (for example a single-colour STL). Name it so (`..._geometry-only-diagnostic.3mf`), state in the report that paint, parts, transforms and project metadata were intentionally dropped, and never present it as the colour-preserving delivery.
2. If the diagnostic shows the mesh is fine and the container is at fault, the delivery is a **repaired colour-preserving sibling**: fix only the suspect element (build-item or component transform, plate offset, object placement, stale plate record) while keeping every paint token, part, other transform and metadata member, and report each changed value. Verify with the face-level round-trip of section A and, when a slicer is available, import, Prepare selection and slice.
3. If the mesh itself is at fault (open edges, inverted winding), repair the painted mesh (`stl-feature-audit-and-edit.md` section 3, `paint-label-repair.md`), not by flattening.

Recipe for the diagnostic sibling only. If the slicer places a valid mesh outside the bed or crashes when the object is selected, treat the container and assembly metadata as suspect separately from the mesh. Preserve the source and canonicalise to the minimal standards-compliant 3MF shape: one resource object, one mesh, one identity-transform build item, millimetres, no stale plate, project or paint metadata. Bake the intended assembled orientation and translate the minimum printable Z to exactly 0 before serialising; do not rely on a slicer-specific plate transform. Validate ZIP CRC, XML and build references, manifoldness and winding, component count and final bounds. A ZIP/XML or geometry audit alone is **not** proof the slicer accepts the result: if the slicer is available require a real import, Prepare selection and slice or Preview; otherwise label it *structurally validated, slicer UI acceptance pending*. Use STL only if its post-export mesh is independently welded and still one connected manifold, since binary STL's duplicated vertex records can mislead a naive connectivity audit.

## E. Delivery gates by claim

| Claim | Minimum evidence |
|---|---|
| "Geometry edited as requested" | Output re-read from disk: ZIP CRC and XML, target dimensions, unchanged other bounds, manifold and consistent winding, hashes of source and sibling |
| "Colour-preserving delivery" | All of the above **plus**: compare resolved per-surface paint and filament meaning against the unmarked source or confirmed final mapping, using face lineage when topology changes (token-count deltas explained); verify the intended part and object count; compare every assembly transform and project-metadata **value** against the source, including printer, process and filament settings, plate and instance assignments, base extruders, palette and coupled arrays. Presence of a key is insufficient. Unchanged ZIP members should match byte for byte; for an intentionally edited XML or config member compare parsed values and report each intentional, scope-authorised change (for example removal of proven-unused marker palette entries and their coupled-array changes). Any unexplained value change fails the gate. Independently verify the allowed mutation scope. `scripts/verify_3mf_paint_cleanup.py` covers only its paint-only, unchanged-topology case, rejects non-paint XML changes, and is not the validator for a geometric or topology edit. A script that was not run is not evidence |
| "Slicer accepts it" | Real slicer import and slice (embedded settings first) with the tool commands in the G-code checked, not the exit code alone; otherwise *structurally validated, slicer acceptance pending* |
| "Prints correctly" | A physical result. None of the above implies it |

## F. Auditing a multi-3MF download package

When a downloaded package has several 3MF files, do not infer required files or plates from names or thumbnails. Treat each 3MF as a ZIP; map plate instances to object names through `Metadata/model_settings.config`; check the printer model, nozzle, filament arrays, support and brim settings and extruder assignments; extract plate previews; run the slicer's information command; and perform a real headless slice from embedded settings, then inspect the result file and the G-code footer for warnings, time and material. Report alternatives separately from mandatory shared parts, and never recommend printing an add-on file wholesale. Preserve supplied placement and orientation for parts near the bed limit (do not auto-arrange), swap author filament profiles for your own calibrated ones, and distinguish an author-documented floating-region warning from a real support need. Check for mutually exclusive template objects (for example a finished badge and a blank customisable one) before printing.
